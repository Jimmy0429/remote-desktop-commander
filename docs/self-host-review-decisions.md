# Decisions from the Fable 5.2 review

The user requested collaboration with their installed Anthropic Fable 5.2. Codex briefed it using a source-only review snapshot, verified the actual model identifier `claude-fable-5-2`, and exchanged challenges and corrections. No runtime credentials, private computer files, or unrelated conversations were included. Raw review transcripts stay in ignored local files.

## Changes supported by reproduced failures

| Finding | Decision and verification |
| --- | --- |
| PID file survived a crash and prevented restart | Hold a SQLite exclusive transaction for the service lifetime. SIGKILL releases the kernel lock; competing and paused live writers remain excluded. Keep the inode and a version marker, including across shutdown. |
| Rejected WebSocket upgrades could retain sockets or crash on reset | Own socket error handling immediately and close rejected sockets after a bounded response flush. Tests cover reset peers and more than 256 half-open attempts. |
| localhost POST Origin was rejected | Admit exact local aliases on the actual local port only when no public origin is configured. Keep configured public origins strict. |
| Offline clients saw no device tools and device descriptions were trusted | Publish a server-owned static catalog; retain only device capability names. Compare all 23 input schemas and operation annotations with the actual engine. |
| Duplicate agents fought through reconnects | Deliver a distinct replacement close code; the replaced agent exits with a diagnostic while the new one remains connected. Ignore stale socket close events. |
| Initial network loss stopped an unattended agent | Retry transient startup/connection failures, with cancellation and explicit diagnostics. Retry HTTP 403 more slowly; invalid credentials and explicit revocation remain fatal. |
| Unknown was used for definite refusals | Report not-started and executed-with-unavailable-output distinctly. A duplicate refusal does not finish the original pending call. |
| A 5 MiB read closed the stdio engine | Bound complete outbound messages before pipe writes. Return an explicit executed/result-too-large response, preserving other terminal sessions and subsequent reads. |
| Missing target could select the wrong sole online computer | Require deviceId for every device tool call, matching the advertised schema. |
| Result pruning repeatedly serialized retained content | Cache each completed result's serialized size. |

## Tradeoffs discussed

- Fable initially proposed time-based stale-lock takeover. Codex challenged it because a paused live process could become a second writer after resuming. Both agreed on a kernel-released lock. Node 22.13 is the minimum because [built-in SQLite no longer needs a flag from that version](https://nodejs.org/api/sqlite.html). The lock database uses DELETE journaling, zero busy timeout, a committed initialization, and a write-free lifetime EXCLUSIVE transaction. Only local filesystems and local Docker named volumes are qualified; do not delete active lock files.
- Legacy PID locks are not silently deleted: an older binary may still be running. A persistent version marker blocks old binaries after migration. This conservative migration rule was retained despite Fable's suggestion to remove obsolete locks automatically.
- Unknown outcomes remain final and operations are never automatically replayed. The normal hard deadline is now 31 minutes, beyond the engine's 30-minute request deadline, so ordinary long work stays running and pollable. Disconnects or a genuine hard deadline still require inspecting state before another side effect. Durable late-result recovery is future work.
- Command and content history remains redacted by default. This avoids retaining secrets, with the explicit cost that the audit cannot reconstruct the full commands or file contents involved in an incident. Opt-in device-local forensic logging needs its own retention and access design.
- A private VPN with TLS and a desktop client is the preferred first deployment boundary. No VPN, permanent host, or persistent client configuration was created by the build task. Public access should wait for further dependency review and separate revocable client credentials; OAuth depends on the chosen client's requirements and should use a maintained implementation.
- Protocol/build-version negotiation, per-client tokens, optional device-side tool profiles, and durable result redelivery remain future features. They are not claimed by this first version.

See [verification results](self-host-verification.md) for test scope and remaining inherited dependency findings. A green test suite does not mean a clean dependency audit or a verified public deployment.

## November 17 Windows checkpoint

The owner asked to prioritize Windows, then deferred actual computer installation until the following day. The checkpoint adds protected Windows storage and a stdio client bridge; it does not install startup tasks, change the owner's desktop-client settings, or deploy a public endpoint.

- Fable prioritized an actual client path and native Windows credential protection. The bridge was exercised by the installed Claude Code client with `claude-fable-5-2` against a disposable Mac fixture: one write and one read completed through the bridge, private server, agent, and engine. No persistent client configuration was changed.
- Fable initially recommended separate client tokens as a bridge prerequisite. Codex challenged that requirement because the approved direct-HTTP design already gave the owner client the same bearer credential. Fable accepted the existing single-owner boundary for this pilot. Independently revocable MCP-only tokens remain a future improvement.
- Both agreed that inherited ACL entries can be accepted when their SIDs and ownership are trusted and checked on credential reads. New private directories are protected before secret writes. Directory permissions, owners, links, and replacement authority matter alongside the file's own permissions.
- Static review did not predict the first Windows CI failure: inbox PowerShell 5.1 could not load an inherited PowerShell module. The helper now pins module resolution to inbox modules before startup and ignores inherited custom module paths; a native test supplies an untrusted Security module and asserts it is never loaded. No execution-policy bypass or relaxation of ACL requirements was introduced.
- Fable identified ancestor replacement risk but initially recommended skipping ancestor owner checks. A separate reviewer showed that a foreign owner has implicit authority to rewrite a DACL even without a dangerous explicit ACE. Codex accepted that correction; Fable explicitly withdrew its earlier recommendation. Every ancestor owner is now checked, with only the exact Windows TrustedInstaller SID additionally trusted for ancestors. The credential directory and its immediate parent keep the stricter owner set. Microsoft documents [owner authority](https://learn.microsoft.com/en-us/windows/win32/ad/security-descriptor-components) and the [TrustedInstaller SID](https://github.com/microsoft/WindowsAppSDK/blob/main/specs/applicationdata/ApplicationData.md).
- Native tests cover broad explicit/inherited grants, null DACLs verified through the Windows API, foreign ownership, unsafe ancestors, junction refusal, registry replacement, and a detached bridge process with piped stdio. The null-DACL fixture originally tried account-name translation for an unmapped Windows ACL entry; it now requests SIDs directly, as production does.
- The Windows bridge timeout was isolated to PowerShell command discovery under the MCP SDK's filtered environment. Native probes proved that stdin reading completed, then `ConvertFrom-Json` discovery stalled. The same filtered environment passed in 398 ms when the three required inbox modules were explicitly loaded by absolute path; restoring only the runner's preloaded analysis cache also passed. The fix uses deterministic inbox imports rather than depending on that cache or extending the 20-second helper limit. The regression retains the SDK environment and exercises a disabled cache. [GitHub's Windows image setup](https://github.com/actions/runner-images/blob/f40a752b24f9f5c2380d5bf53f91353ca122f7e7/images/windows/scripts/build/Configure-PowerShell.ps1) explains its cache warmup; sanitized native receipts are retained locally.
- Fable accepted that minimum fix and suggested disabling automatic module loading so any missing command fails promptly. Independent review then caught a dependency in the error handler: an unavailable Utility module must not trigger `ConvertTo-Json` discovery while reporting its own failure. The handler now emits only fixed JSON and a controlled reason code; a native regression deliberately supplies a missing inbox manifest and requires a closed, redacted failure.
- Test subprocess initialization is bounded at 30 seconds; tool and network limits are unchanged. Windows test-file concurrency is capped at two, and phase timings identify future failures. Measure cold startup against the actual AI client's timeout on the owner's PC; CI timing is not a performance guarantee.
- Windows autostart remains deferred until the manual pilot works. It needs normal-user identity, one-instance behavior, explicit start/stop/uninstall controls, battery/runtime settings, and no restart loop following revocation or replacement.

Fable's source-only reviews are advisory, not execution evidence. The final verification report distinguishes native CI, the disposable real-client run, and the still-unperformed installation on the owner's Windows computer.
